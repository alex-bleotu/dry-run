# Dry Run

A desktop app for practicing timed C++ coding interview problems. Pick a problem, the timer starts, write your solution in the built-in editor and run it against visible and hidden tests.

## Features

- Problem menu with several problems, each split into collapsible parts
- Monaco editor with the includes and `main` folded away, so you only write `solve`
- One timer per problem, saved when you leave and reset only with the reset button
- Visible tests show input, expected and actual output side by side
- Hidden tests only tell you pass or fail
- Custom tab to run your code on your own input
- Your code and time are stored per problem and survive restarts

## Requirements

Dry Run compiles your code with `g++` (`-std=c++17 -Wall -Wextra -Werror -O2`), so a C++ compiler must be on your `PATH`.

- Linux: `sudo apt install g++`
- Windows: install MinGW-w64 and add its `bin` folder to `PATH`

## Download

Get the Linux AppImage or the Windows installer from the [releases page](https://github.com/alex-bleotu/dry-run/releases).

On Linux, make the AppImage executable first:

```
chmod +x dry-run-*-linux.AppImage
./dry-run-*-linux.AppImage
```

## Run from source

```
npm install
npm start
```

## Problems

Each problem is a folder in `problems/`:

```
problems/<id>/
  meta.json      title, summary, difficulty, order and the names of the input lists
  problem.md     the statement; "## Part N: ..." sections become collapsible
  starter.cpp    the code you start with (reset restores it)
  tests/         visible.json, hidden.json and optional mine.json
```

Your own solutions are saved in the app data folder, not in the repository.

To add a problem, create a folder with those files. It shows up in the menu on the next start.

Tests are generated by `tools/<id>/generate-tests.js` from a reference solution (`reference.js` and an independent `reference.cpp`). Run `npm run generate-tests` to regenerate them and `npm run check` to run every `reference.cpp` against its tests.

## Build

```
npm run dist:linux
npm run dist:win
```

Pushing a tag like `v1.0.0` builds both installers on GitHub Actions and attaches them to a release.
