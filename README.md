# Dry Run

A desktop app for practicing timed C++ coding interview problems. Pick a problem, the timer starts, write your solution in the built-in editor and run it against visible and hidden tests. It also runs as a [website](#website).

## Features

- Problem menu with several problems, each split into collapsible parts
- Monaco editor with the includes and `main` folded away, so you only write `solve`
- One timer per problem, saved when you leave and reset only with the reset button
- Visible tests show input, expected and actual output side by side
- Hidden tests only tell you pass or fail
- Custom tab to run your code on your own input
- Your code and time are stored per problem and survive restarts
- New and updated problems are downloaded from this repository, so you do not need a new release for more problems
- The app updates itself: new versions download in the background and install when you restart
- Works on phones too: the website switches to Problem, Code and Output tabs on small screens

## Requirements

Dry Run compiles your code with `g++` (`-std=c++17 -Wall -Wextra -Werror -O2`), so a C++ compiler must be on your `PATH`.

- Linux: `sudo apt install g++`
- Windows: install MinGW-w64 and add its `bin` folder to `PATH`

## Download

Get the Linux AppImage or the Windows installer from the [releases page](https://github.com/alex-bleotu/dry-run/releases).

On Linux, make the AppImage executable first:

```
chmod +x dry-run-*-linux.AppImage
./dry-run-*-linux.AppImage
```

### Updates

From version 1.1.0 on, the Windows installer and the AppImage keep themselves up to date. On start and every few hours the app checks this repository's latest release. When there is a newer version it downloads it in the background and shows a "Restart to update" button in the menu; if you skip it, the update is installed when you quit. Your code and timers are kept. Copies running from source do not update themselves.

Version 1.0.0 cannot update itself, so install 1.1.0 from the releases page once.

To release a new version, bump `version` in `package.json` and commit, then push a tag like `v1.2.0` or press **Run workflow** on the Release workflow in the Actions tab (it releases the version in `package.json` and creates its tag). The release workflow builds both installers and uploads them together with `latest.yml`, `latest-linux.yml` and the `.blockmap` files, which the installed apps read to find the update.

## Problems

Each problem is a folder in `problems/`:

```
problems/<id>/
  meta.json      title, summary, difficulty, order and the names of the input lists
  problem.md     the statement; "## Part N: ..." sections become collapsible
  starter.cpp    the code you start with (reset restores it)
  tests/         visible.json, hidden.json and optional mine.json
```

Your own solutions are saved in the app data folder, not in the repository.

To add a problem, create a folder with those files, then run `npm run generate-tests` (or `npm run manifest` if you only edited text) to refresh `problems/index.json` and commit it. It shows up in the menu on the next start.

### Problem updates

On start, and when you press "Check for new problems", the app reads `problems/index.json` from this repository's `main` branch. Every problem that is new, or whose files changed, is downloaded into the app data folder. Each file is checked against the SHA-256 in the manifest, and only `meta.json`, `problem.md`, `starter.cpp` and the two test files are accepted. Your own solutions and timers are never touched by an update.

Downloaded problems replace the bundled copy of the same id. They are cleared when you install a new version of the app, which brings its own bundled problems.

Tests are generated by `tools/<id>/generate-tests.js` from a reference solution (`reference.js` and an independent `reference.cpp`). Run `npm run generate-tests` to regenerate them and `npm run check` to run every `reference.cpp` against its tests.

## Website

Dry Run also runs as a website, with nothing to install. The same interface is served as static files, and C++ is compiled in the browser by Clang built for WebAssembly ([@yowasp/clang](https://github.com/YoWASP/clang)), so no server is involved and code never leaves the browser.

```
npm install
npm run build:web
npm run preview:web
```

Then open http://localhost:8080. `build:web` writes the site to `web-dist/`; the first build takes about a minute because it precompiles `<bits/stdc++.h>`.

Differences from the desktop app:

- The first visit downloads the compiler (about 37 MB); the browser caches it after that
- A compile takes about 3 seconds instead of about 2
- Code is compiled with Clang 21 and `-fno-exceptions`, because the WebAssembly C++ library has no exception support: `try`/`catch` does not compile, and errors that would throw (a failed `stoi`, `.at()` out of range) abort the program
- `<bits/stdc++.h>` is provided by Dry Run and includes every standard header except `<csetjmp>` and `<csignal>`
- Very deep recursion runs out of the browser's stack sooner than a native program would
- Your code and time are saved in the browser, per site
- There is no "Check for new problems" button: the website gets new and updated problems each time it is redeployed

### Deploy on Netlify

The repository includes `netlify.toml`, so in Netlify choose **Add new site → Import an existing project**, pick this repository and deploy. The build command (`npm run build:web`) and publish directory (`web-dist`) are read from the file. Every push to the chosen branch redeploys the site.

`web-dist/` is plain static files, so any static host works the same way.

